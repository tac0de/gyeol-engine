# 결 엔진의 현재 가치와 공개 전략 평가

2026-10-25 소스 관찰에 근거한 평가입니다. 시장 수요나 개발 시간 단축을 측정한 결과가 아닙니다.

## 판단

**내부 게임을 만드는 작은 실행·검증 기반으로는 의미가 있습니다. 독립적인 범용 웹게임 엔진 제품으로서의 가치는 아직 입증되지 않았습니다.**

현재 가장 설득력 있는 축은 'AI가 소스에 접근할 수 있다'가 아니라, 게임의 같은 규칙을 화면·자동 검사·시나리오·기록 재생에서 실행하고, 실패를 재현해 수정하는 흐름입니다. 이는 실제 게임의 규칙 오류와 회귀를 줄이는 데 쓸 수 있는 구체적인 메커니즘입니다. 다만 자동 검사 성공은 재미·미술·빠른 개발을 증명하지 않습니다.

UI, 저장, 템플릿을 추가했다는 사실만으로 차별적인 엔진이 되지는 않습니다. Phaser는 이미 웹2D의 렌더링·scene·입력·로딩 등의 폭넓은 기반을 제공합니다. 같은 기능을 계속 따라 만드는 전략은 유지비가 크며, 에이전트는 기존 도구도 사용할 수 있습니다. 현재 결 엔진에는 범용 렌더러/에디터/에셋 생태계·여러 브라우저/장르 검증·외부 사용 경험이 부족합니다.

## 관찰한 근거와 아직 없는 근거

- 주 소비 프로젝트 thedivineparadox의 package.json은 아직 0.4.0 설치 파일을 참조합니다. 여러 게임이 core/browser API를 사용하고, 삼국패는 실제 전투 판정기를 화면·AI·자동 대전·재생에서 공유합니다. 따라서 작은 공통 실행 기반의 내부 쓰임은 있습니다.
- 최근 0.6 UI와 이번 0.7 저장은 독립 생성 예제를 기준으로 검사합니다. 주 소비 프로젝트에 적용해 실제 중복/버그/개발 시간이 줄었는지는 아직 관찰하지 않았습니다.
- 주 소비 프로젝트에는 별도 계정/서버 저장 경계도 있습니다. 이번 브라우저 저장을 그 정책의 대체물로 넣어서는 안 됩니다. 게임별 저장 스키마와 서버 동기화는 실제 소비자에서 검토해야 합니다.
- 외부 사용자 완주, 서로 다른 독립 게임의 완성 경험, 다른 엔진 대비 생산성, 장기 API 유지비는 아직 미측정입니다. 공개 저장소와 검사 수만으로 외부 효용을 인증할 수 없습니다.

## 추천: 내부 실게임 주도 + 공개 experimental 패키지

현재는 공개 저장소를 독립 제품처럼 키우는 것보다 **thedivineparadox의 실제 게임을 우선하는 개발**이 낫습니다. 다만 이미 분리한 작은 패키지 경계와 MIT 공개 소스는 실험·재사용·재현에 유용하므로 유지할 수 있습니다. '내부 우선'과 '공개 소스'는 함께 가능합니다.

이 추천은 저장소 비공개 전환, 라이선스 변경, 소비 프로젝트의 즉시 이관을 실행하자는 뜻이 아닙니다. 이번 요청에서는 평가만 하며 사용자 선택을 대신하지 않습니다.

| 내부 요구 주도, 작은 공개 패키지 유지 | 실게임 문제로 검증하며 독립 검사·재사용 유지 | 버전/설치 연결 비용은 남음 | 현재 추천 |

## 다음 판단을 바꾸는 실제 실험

1. **삼국패 같은 대표 게임 하나에 적용:** 화면/복구가 실제로 막히는 구간부터 필요한 API만 채택합니다. 기존 계정/서버 저장과 게임 규칙은 보존합니다. 이 이관은 별도 작업입니다.
2. **기준을 먼저 기록:** 같은 종류의 변경에서 반복 코드, 재현하기 어려운 오류, 수정/검사 반복, 설치·업그레이드 때문에 든 작업을 함께 기록합니다. 이득과 패키지 유지비를 같은 장부에 둡니다.
3. **두 번째 게임에서 확인:** 같은 도구가 자연스럽게 재사용되는지, 게임마다 예외 설정/복사 코드가 더 늘어나는지 봅니다. 범용화를 위해 게임 품질을 미루지 않습니다.
4. **효과가 확인되면 외부 공개 베타:** 독립 게임 2개와 외부 사용자 완주 기준을 적용합니다. 에이전트가 명확한 소스·검사·재현 경로를 이용하는 이점이 실제로 나타날 때 공개 도구로 설명합니다.
5. **효과가 약하면 범위를 줄임:** 일반 렌더링/편집 기능의 추격을 중단하고 규칙·검사·재현 도구만 남기거나 내부 모듈로 단순화합니다. 지금 구현한 양은 계속 확장할 이유가 아닙니다.

따라서 현재 결 엔진을 'Phaser 대체 엔진'으로 홍보하는 것은 이릅니다. **우리 게임의 개발을 돕는 재현 가능한 실행·검사 기반**이라는 좁은 주장을 먼저 입증하는 편이 정직하고 실용적입니다.

## 최신 사용자 결정과 첫 개선

2026-10-25 사용자는 Phaser 도입을 철회하고 결을 유지하기로 확정했다. 화면·연출, 실제 플레이/로딩, 제작·검사 반복 비용을 모두 실게임 기준으로 개선한다. 이 결정은 위의 미측정 효용·외부 사용·비교 성능 한계를 제거하지 않는다. 0.8의 좁은 개선과 측정 범위는 [runtime work](performance.md)에 기록한다. 앞선 Phaser 실험은 역사적 비교 자료이며 현재 도입 지침이 아니다.
